# AENHT 0.2.2-beta.1：条漫自动滚动预发布

这是用于继续收集反馈的小更新，标记为 GitHub **Pre-release**，不是正式稳定版。已发布的 `v0.2.1` 保留原有正式版状态、标签和安装包。

## 版本与后续更新

- 下载版本：`0.2.2-beta.1`，构建号 `5`。
- 两端 App 内显示 `0.2.2-beta.1`；iOS 系统的数字版本字段保留 `0.2.2`，构建号为 `5`。二者对应同一批源码。
- 不必为每条反馈升级一个正式版本。后续日常测试可以继续使用现有 `dev-latest` 预发布渠道、只增加构建号；有阶段性结果时发布 `beta.2`、`beta.3`，稳定后再发布 `0.2.2`。
- 不建议将已经正式发布的 `0.2.1` 事后改成测试版，也不建议使用 `0.2.0_1`、`0.2.1_1` 等非标准补丁编号。

## 本次包含的改进

1. 阅读设置中，自动滚动速度下方新增“滑动时继续自动滚动”，默认关闭。打开后，手动拖动和惯性期间由用户控制位置，结束后继续自动滚动。开关支持保存、备份和同步。
2. 3 秒/屏及更快时，在速度值前显示红色“可能速度过快，无法正常阅读”，数值也使用红色。
3. 条漫跨图不再立即隐藏上下栏，继续按照设置的隐藏时间处理。
4. iOS 自动滚动使用原生滚动视图的实际位置；两端保留已解码图片的尺寸，避免已看图片回到占位高度。
5. 针对第一次测试仍有高速抖动的反馈，进一步用实际位移反馈补偿 UIKit 的像素取整误差，仅保留一个像素以内的余量，不积累加载等待或布局校正造成的偏移；同时减少重复坐标扫描和重复锚点分配。模拟器证明了直接去掉取整会丢失距离，不能用这种方式保证流畅。
6. 保留手动接管、加载等待、失败重试、末页停止和后台暂停等边界行为，新增对应的连续位移和页码进度回归检查。
7. 修正 beta/正式版的版本比较，确保后续 `0.2.2` 能被 `0.2.2-beta.1` 识别为更新；iOS 的关于、更新和诊断界面统一显示 beta 标识。正式发布时清空 `AENHT_PRERELEASE`，Android 去掉版本名称中的 beta 后缀。

## 仍待确认

**尚不能确认高速抖动已经彻底修复。** 本地没有连接 iPad 2021，模拟器可以验证位移与状态逻辑，不能代替实机的显示流畅度、图片解码和 GPU 帧时间检查。本次作为进一步优化后的预发布版本交由使用者复测。

如果仍有抖动，请继续在 Issue #7 下反馈速度档位、是否只在图片交界处出现、图片是否已加载，以及设备/系统信息；方便时附一段录屏。Issue 保持打开，后续继续改进。

## 在同一个 Issue 下回复

登录 GitHub，打开 [Issue #7](https://github.com/AtlanYuey/AENHT/issues/7)，滑到页面底部，在“添加评论 / Add a comment”输入框写下情况，再点“评论 / Comment”。手机上若看不到输入框，先登录后刷新页面。可以一直在这一条下面继续回复，不必为每次反馈新建 Issue。
